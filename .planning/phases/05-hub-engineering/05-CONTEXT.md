<decisions>
## Implementation Decisions

### Locked Decisions

- **D-01 (HUB-01 spec):** Write a spec (prefer `docs/HUB_RECOMMENDATIONS.md`) that defines the ranking signal in full: **connectivity**, **harvest**, and **curator score**. State which of those three the v1 prototype actually computes. The spec must say the list is **contributor tooling**, not a scientific ranking (same honesty as the orphan/xref panel).
- **D-02 (v1 ranking = connectivity):** The prototype ranks **bridges** by **undirected degree in `docs/knowledge_graph.json`** (or the same node/edge set `build_graph.py` already exports). Higher degree = higher “leverage for a contributor looking where to connect next.” Harvest rank and curator score are **specified as future slots** (null / omitted on v1 items), not fake numbers.
- **D-03 (static JSON, not browser graph math):** Commit `api/v1/recommendations.json` generated by a Python exporter (analog: `scripts/export_orphan_xref_panel.py`). Hub **fetches** the file. Do not compute degree in the browser. Do not call an LLM.
- **D-04 (schema):** JSON has at least `generated_at`, `source`, `ranking` (string naming the v1 signal), `disclaimer`, and `items[]`. Each item has `id` (bridge id `b-…`), `title` or graph label, `score` (degree, integer), `kind: "bridge"`, and a GitHub blob or search URL. Cap **≤ 25** items.
- **D-05 (hub slice):** Add a small section on `dashboard/index.html` (new `#recommendations` or similar) that copies the **orphan/xref fetch + table/empty/status** pattern. Do **not** redesign nav, hero, Crosscheck grid, or graph. Copy existing CSS variables / card styles. Dark theme only.
- **D-06 (honesty):** Visible copy must include that this is **not** a scientific ranking and **not** a CONFIRMED/INCONCLUSIVE outcome. Do not mix Crosscheck RESULT tokens into recommendation scores.
- **D-07 (regenerate path):** Document `python scripts/export_recommendations.py` (name may match analog). Add the script to `docs/DEV_DASHBOARD.md` playbook (promote Phase C stub from planned → shipped thin slice). Optional: mention in `build-graph.yml` only if that is a one-line analog to `export_orphan_xref_panel.py`; do not redesign CI.
- **D-08 (smoke):** Add `tests/repo_smoke` shape check analog to `test_orphan_xref_panel_json` (file exists, required keys, item cap, ids look like `b-`). No live Monte Carlo. No epidemic edits.
- **D-09 (API index):** Register the endpoint in `api/v1/meta.json` `endpoints` if that file is the index of API paths. Keep `generate_api.py` comment in sync if it lists panel JSON files.
- **D-10:** No marketing, DNS, arXiv, catalog waves, JS runners, promote CLI, epidemic retune, or fabricated `RESULT: CONFIRMED`.
- **D-11:** After hub HTML/stats edits: `python scripts/verify_dashboard_consistency.py`. Do **not** run `build_crosscheck.py --apply` unless Crosscheck marker blocks change (they must not).
- **D-12:** ROADMAP plan: **05-01** Spec + thin JSON slice in hub. One plan is enough unless the planner must split spec vs exporter vs hub (then still one wave or spec-then-wire).

### Claude's Discretion

- Exact filename (`docs/HUB_RECOMMENDATIONS.md` vs a section in `docs/DEV_DASHBOARD.md`). Prefer a dedicated spec file linked from DEV_DASHBOARD.
- Degree vs weighted degree (if graph edges already have a simple weight). Prefer unweighted undirected degree unless RESEARCH finds a one-line existing metric in `build_graph.py`.
- Table vs card list in the hub section — copy whichever orphan/xref already uses.
- Whether to add the exporter to `build-graph.yml` this phase (nice-to-have; smoke + documented command is enough).

### Deferred Ideas

- Harvest-rank and curator-score **implementation** (specify only)
- Personalized / logged-in recommendations
- Computing rankings in the browser from `graph.json`
- Novelty scoring, ML, embeddings
- Hub visual redesign / light theme / new design system
- Feeding Crosscheck RESULT into recommendation scores
</decisions>
