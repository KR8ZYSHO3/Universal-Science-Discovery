### Pattern 1: Static panel exporter (orphan analog)

**What:** A small Python script writes capped JSON; the hub never walks the catalog.

```python
# Source: scripts/build_graph.py top_nodes_by_degree (lines 184–200)
degree: dict[str, int] = defaultdict(int)
for edge in edges:
    degree[edge["source"]] += 1
    degree[edge["target"]] += 1
```

Then restrict to nodes with `type == "bridge"`, sort `(-degree[id], id)`, `[:25]`. Handle `source`/`target` as strings (committed JSON).
```python
# Source: scripts/build_graph.py lines 184–200 + docs/knowledge_graph.json shape
from collections import defaultdict
from pathlib import Path
import json

graph = json.loads(Path("docs/knowledge_graph.json").read_text(encoding="utf-8"))
nodes = graph["nodes"]
edges = graph["edges"]
degree: dict[str, int] = defaultdict(int)
for edge in edges:
    s, t = edge.get("source"), edge.get("target")
    sid = s if isinstance(s, str) else (s or {}).get("id", "")
    tid = t if isinstance(t, str) else (t or {}).get("id", "")
    if sid:
        degree[sid] += 1
    if tid:
        degree[tid] += 1

bridges = [n for n in nodes if n.get("type") == "bridge" and str(n.get("id", "")).startswith("b-")]
ranked = sorted(bridges, key=lambda n: (-degree.get(n["id"], 0), n["id"]))[:25]
```

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: Using `top_nodes_by_degree` as a black box
**What goes wrong:** Top 25 nodes include unknowns/hypotheses; bridge cap underfills or mixes kinds.
**Why it happens:** Helper is type-agnostic; `main()` prints “Top 5 most-connected **nodes**”.
**How to avoid:** Copy the increment loop; filter `type == "bridge"` (and `id` prefix `b-`).
**Warning signs:** Smoke sees `kind != "bridge"` or ids starting `u-` / `h-`.

### Pitfall 2: `generate_api.py` drops the endpoint
**What goes wrong:** First commit registers `recommendations` in `meta.json` by hand; next graph-bot run rewrites `meta.json` from the hardcoded `endpoints` dict and the key disappears.
**Why it happens:** `generate_api.py` is the only writer of `meta.json` `endpoints`; it does not merge unknown keys. `pages.yml` only adds `pages_deploy`.
**How to avoid:** Edit `scripts/generate_api.py` docstring **and** `endpoints` dict in the same change. Do **not** teach `generate_api.py` to copy/write `recommendations.json` (orphan is not copied either).
**Warning signs:** Hub API list and `meta.json` disagree after a bot PR.

### Pitfall 3: DOM XSS via catalog titles
**What goes wrong:** `tr.innerHTML = '<td>' + item.title` executes markup if a YAML title ever contains `<` / `onerror=`.
**Why it happens:** Other hub widgets (`innerHTML` search cards, graph panel) already mix HTML; a copier might follow those, not the orphan panel.
**How to avoid:** Clone the orphan IIFE only. `textContent` for `title`, `id`, `score`, disclaimer, status. Allow `a.href` only when the URL starts with `https://github.com/`.
**Warning signs:** `innerHTML` or string-concatenated HTML in the new IIFE.

### Pitfall 4: MkDocs `--strict` on a new spec file
**What goes wrong:** `docs/HUB_RECOMMENDATIONS.md` is added but omitted from `mkdocs.yml` `nav`; CI `mkdocs-build.yml` fails (`omitted_files: warn` + `strict: true`).
**Why it happens:** Discretion prefers a dedicated spec; nav is easy to forget.
**How to avoid:** Add under Operations next to Dev dashboard: `- Hub recommendations: HUB_RECOMMENDATIONS.md`. Run `mkdocs build --strict`.
**Warning signs:** `INFO - The following pages exist in the docs directory, but are not included in the nav configuration` treated as error.

### Pitfall 5: Honesty drift / Crosscheck contamination
**What goes wrong:** Section title sounds like “best bridges scientifically”; scores shown next to CONFIRMED badges.
**Why it happens:** Pillar 3 “awesome hub” pressure vs D-06.
**How to avoid:** Mirror orphan wording (“not a scientific ranking”). Footer can show `Generated:` + `ranking=undirected_degree` + cap. Never display `RESULT:` in this section. Do not change Crosscheck markers (D-11).
**Warning signs:** Copy containing CONFIRMED/INCONCLUSIVE as if they were ranking inputs.

### Pitfall 6: Loading the full graph in the browser “just for now”
**What goes wrong:** Extra `fetch('../api/v1/graph.json')` to recompute degree, plus layout work.
**Why it happens:** Graph JSON is already fetched for D3; tempting to “reuse”.
**How to avoid:** D-03. The recommendations IIFE fetches only `recommendations.json`.
**Warning signs:** New fetch of `graph.json` inside the recommendations script.

### Pitfall 7: verify_dashboard_consistency false confidence
**What goes wrong:** New section is added but snap/stat numbers were accidentally edited; CI fails. Or the reverse: HTML is broken but consistency still passes because it only checks `snap-*` / `stat-*` / pills.
**Why it happens:** Guardrail is count-alignment, not panel JS.
**How to avoid:** Do not touch snap/stat/hero pill markup. Still run the script (D-11). Manually open `/dashboard/#recommendations` over `http.server`.
**Warning signs:** Diff in `id="snap-` or `id="stat-` spans.

### Pitfall 8: Epidemic / CONFIRMED-grep drive-by
**What goes wrong:** Unrelated Crosscheck files appear in the PR.
**Why it happens:** Broad greps, “while we’re here”.
**How to avoid:** D-10. Phase 4 already closed TRUST-02/03. This phase’s file list is hub/docs/api/exporter/smoke only.
**Warning signs:** Diffs under `repro/`, `protocols-catalog/`, `crosscheck-repro.yml`.
</common_pitfalls>

<security_domain>
## Security Domain

Static public JSON + client fetch. No auth, no sessions, no user accounts (deferred). Catalog titles are **untrusted text** from git YAML and must be treated as such in the DOM.

### Applicable ASVS Categories

Template 4.x IDs (agent checklist) plus ASVS 5.0.0 (May 2025) mapping:

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication (5.0 V6) | no | Public Pages JSON; no login |
| V3 Session Management (5.0 V7) | no | No cookies/sessions in this slice |
| V4 Access Control (5.0 V8) | no | Same public read as the rest of `api/v1/` |
| V5 Input Validation / 5.0 **V3.2 Unintended Content Interpretation** | **yes** | Render item `title` / `id` / `disclaimer` with `element.textContent` / `createTextNode`. Never `innerHTML`. [CITED: OWASP ASVS 5.0.0 `3.2.2`; OWASP DOM XSS Prevention Cheat Sheet RULE #6] |
| V6 Cryptography (5.0 V11) | no | No secrets, no tokens. HTTPS is GitHub Pages default |
| 5.0 V4 API | thin | Static file; no query params, no injection into SQL. Shape-check in pytest |

### Known Threat Patterns for static JSON hub panels

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| DOM XSS via `item.title` (bridge claims contain quotes, `<`, math) | Tampering / Information disclosure | `textContent` only; clone orphan IIFE, not search-card `innerHTML` [CITED: https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/DOM_based_XSS_Prevention_Cheat_Sheet.md] |
| `javascript:` or `data:` URL in `github_blob_url` | Elevation of privilege (drive-by) | Exporter builds URLs from `https://github.com/{owner}/{repo}/…` only. Hub sets `a.href` iff `url.indexOf('https://github.com/') === 0`. `rel="noopener"` + `target="_blank"` as orphan. |
| Confused deputy: treating degree as a scientific finding | Spoofing / repudiation of methodology | D-06 disclaimer in JSON **and** visible hub copy; no Crosscheck tokens in scores |
| Prototype pollution / unexpected JSON types | Tampering | `items` must be an array; skip non-objects; `score` displayed via `textContent` of `String(int)` |
| Fetching `graph.json` in the panel | Denial of service (main-thread parse of 2.8 MB) | D-03: fetch only `recommendations.json` |

**Do not** add DOMPurify, CSP headers, or Trusted Types this phase — the orphan panel has none, and the sink is text. Do not copy graph-panel `innerHTML` + `esc()` unless you are not touching that code.

Reports still go through `SECURITY.md` (private GitHub advisory / `security@usdr.dev`), not a public issue. [VERIFIED: `SECURITY.md`]
